# RTK multi-harness integration plan

## Problem

RTK is installed and works transparently in Claude Code through the guarded
`PreToolUse` hook in `claude/.claude/settings.json`, but the other coding
harnesses configured by this repository do not currently have equivalent
command-rewrite integrations:

- Cursor Agent has no `~/.cursor/hooks.json` RTK `preToolUse` hook.
- pi has no RTK `tool_call` extension.
- opencode has no RTK `tool.execute.before` plugin.
- omp has no upstream RTK target and therefore needs a small native extension
  if Bash calls there should be rewritten too.

OpenRouter is not another integration target. It is the model provider used by
opencode, pi, and omp; RTK acts at each harness's shell-tool boundary, before
provider traffic. Herdr and sidekick.nvim are launchers/multiplexers, so they
inherit the integration of whichever harness they start and need no RTK hook.

The installed RTK is `0.43.0`; Homebrew currently offers `0.45.0`. The Brewfile
already carries unpinned `brew "rtk"`, so upgrading is a machine action, not a
formula change.

## Outcome

One `brew bundle`/Stow checkout supports transparent RTK rewriting in Claude
Code, Cursor Agent, pi, opencode, and omp without allowing RTK's initializer to
rewrite repo-owned configuration or install a duplicate Claude hook.

Each adapter remains deliberately thin: it only sends the original shell
command to `rtk rewrite` or `rtk hook <host>`. All rewrite rules and output
filtering remain owned by the installed RTK binary.

## Decisions

- **Keep the existing Claude hook unchanged.** Its guarded command is portable
  across machines without RTK. RTK's own `--show`/`gain` detection may report
  it as absent because it recognizes only the exact unguarded command, but
  `rtk verify` confirms the native hook and its tests pass.
- **Do not run `rtk init -g --agent cursor` against the live config.** With
  RTK 0.43.0, its dry run attempted to append a second unguarded Claude hook
  because it did not recognize the repo's guarded wrapper. Use the upstream
  Cursor hook payload, but deploy it through this repo.
- **Track static adapters with their owning Stow packages.** Cursor's hook,
  pi's extension, opencode's plugin, and omp's extension are durable policy,
  not credentials or mutable runtime state. `stow --no-folding` already keeps
  each parent directory real, allowing these links to coexist with each
  harness's machine-written files.
- **Vendor thin generated adapters, not RTK internals.** The pi and opencode
  files generated by `rtk init --dry-run` delegate to `rtk rewrite`; they do
  not duplicate the rewrite registry. Preserve a header recording the RTK
  version used to refresh them and the upstream generation command.
- **Port, do not blindly copy, the pi adapter to omp.** pi imports
  `@earendil-works/pi-coding-agent`; omp imports
  `@oh-my-pi/pi-coding-agent`. Confirm omp's current `tool_call` mutation and
  `pi.exec` contracts from its installed types/source, then use those native
  contracts. Do not add a compatibility shim between package names.
- **Fail open when RTK is absent, old, times out, or declines a rewrite.** A
  missing optimizer must never break a shell command. Log one concise load-time
  warning for a missing/unsupported binary; unexpected per-call errors pass the
  original command through.
- **Never rewrite an already-prefixed `rtk ...` command.** This prevents loops
  and makes explicit `rtk proxy ...` or `rtk gain` calls authoritative.
- **Honor `RTK_DISABLED=1` in pi, opencode, and omp adapters.** This provides a
  session-local escape hatch without changing tracked configuration. Verify
  whether the upstream Cursor hook already honors it before documenting it for
  Cursor.
- **Keep native file/search tools native.** RTK hooks only shell/Bash calls.
  Cursor/pi/opencode/omp `read`, `grep`, `glob`, LSP, and similar structured
  tools should not be routed through RTK.

## Files

### Add

- `cursor/.cursor/hooks.json`
  - Cursor schema version `1`.
  - One `preToolUse` entry: matcher `Shell`, command `rtk hook cursor`.
  - No Claude/sidekick notification hooks; Cursor already merges the supported
    notification hooks from `~/.claude/settings.json`.
- `pi/.pi/agent/extensions/rtk.ts`
  - Start from the exact adapter emitted by
    `rtk -v init -g --agent pi --dry-run` after upgrading RTK.
  - Probe RTK once at extension load.
  - Intercept only the `bash` tool, call `rtk rewrite`, and revise the command
    only for RTK's documented rewrite exit codes.
- `opencode/.config/opencode/plugins/rtk.ts`
  - Start from the exact adapter emitted by
    `rtk -v init -g --opencode --dry-run` after upgrading RTK.
  - Intercept only `bash`/`shell` in `tool.execute.before` and mutate only the
    command field.
- `omp/.omp/agent/extensions/rtk.ts`
  - Native omp port of the pi adapter using
    `@oh-my-pi/pi-coding-agent` types and omp's actual `tool_call` contract.
  - Same RTK probe, timeout, exit-code, recursion, disable, and fail-open
    behavior as the pi adapter.

### Update

- `README.md`
  - Promote RTK from a Claude-only subsection to a cross-harness section while
    preserving the manual `rtk-token-optimizer` anchor.
  - Add the Cursor, pi, opencode, and omp deployment paths and explain that
    OpenRouter/Herdr/sidekick need no separate integration.
  - Add each new tracked file to its harness's “What's managed” table.
  - Update fresh-machine setup: `brew bundle`, Stow the existing packages, and
    run `rtk init -g --no-patch` only to refresh Claude's machine-local
    `RTK.md`; do not run host initializers that patch repo-owned files.
  - Document the guarded-Claude-hook false warning from `rtk gain` and the
    duplicate-hook hazard.
  - Document `RTK_DISABLED=1` only for adapters verified to honor it.
  - Add exact verification commands and expected evidence.
- `Brewfile`
  - Change the RTK comment from “Claude Code token optimizer” to
    “coding-harness shell-output optimizer.”
  - Keep the formula unpinned.
- `claude/tests/settings-invariants.sh`
  - Retain the invariant that exactly one Claude Bash hook contains
    `rtk hook claude` and that it is guarded by `command -v rtk`.
  - Do not relax this test to accept the duplicate unguarded hook RTK's

- Harness setup documentation/comments as necessary
  - Cursor: state that `hooks.json` is stowed and independent of the
    machine-local `cli-config.json` managed by `setup-statusline.sh`.
  - pi/opencode/omp: describe the new RTK adapter next to the existing
    repo-owned extension/plugin in each managed-files table.

## Implementation phases

### Phase 1 — Refresh and capture upstream adapters

- [ ] Run `brew upgrade rtk`; record `rtk --version` in implementation notes.
- [ ] Re-run dry previews for Cursor, pi, and opencode with global `-v` before
      `init`; confirm paths and payloads without writing:

  ```bash
  rtk -v init -g --agent cursor --dry-run
  rtk -v init -g --agent pi --dry-run
  rtk -v init -g --opencode --dry-run
  ```

- [ ] Compare the upgraded dry-run payloads with the 0.43.0 payloads captured
      during planning. Pay particular attention to rewrite exit codes,
      timeout handling, permission decisions, and supported host event names.
- [ ] Run `rtk init -g --agent cursor --show` and `rtk verify`; preserve the
      existing Claude hook rather than accepting any proposed settings patch.
- [ ] Inspect `rtk rewrite --help` and `rtk hook cursor --help` from the upgraded
      binary. Treat those installed interfaces as authoritative for adapters.

### Phase 2 — Cursor hook

- [ ] Add the upstream Cursor `hooks.json` payload under the `cursor` Stow
      package.
- [ ] Confirm the file does not collide with a machine-local regular
      `~/.cursor/hooks.json`. If a divergent file exists, stop and reconcile it
      rather than overwriting or adopting it.
- [ ] Restow with `stow --no-folding cursor` and confirm the live file resolves
      to this checkout.
- [ ] Validate JSON with `jq empty` and assert exactly one `Shell` RTK
      `preToolUse` entry.
- [ ] Confirm Cursor's existing status line and Claude-derived sidekick
      notification hooks remain unchanged; RTK owns only shell rewriting.

### Phase 3 — pi extension

- [ ] Add the refreshed upstream-generated `rtk.ts` to
      `pi/.pi/agent/extensions/` with no local rewrite rules.
- [ ] Check imports against installed pi `0.84.1` or newer and format using the
      repository's existing TypeScript style.
- [ ] Restow `pi`; confirm the extension coexists with `claude-footer.ts`,
      `nvim-notify.ts`, package-installed extensions, and Herdr's machine-local
      extension.
- [ ] Launch pi and verify the extension loads without a startup warning.
- [ ] Exercise one rewritten Bash command and one unsupported command that must
      pass through unchanged.
- [ ] Repeat with `RTK_DISABLED=1`; the command must remain unmodified.

### Phase 4 — opencode plugin

- [ ] Add the refreshed upstream-generated plugin beside
      `nvim-notify.ts`; do not add plugin registration to `opencode.json` unless
      current opencode documentation proves directory auto-discovery is no
      longer sufficient.
- [ ] Confirm compatibility with installed opencode `1.18.10` or newer and its
      current `tool.execute.before` payload.
- [ ] Restow `opencode`; ensure neither `opencode.json` nor credentials are
      rewritten.
- [ ] Launch opencode and verify both plugins load without warnings.
- [ ] Exercise rewritten, passthrough, already-RTK-prefixed, and disabled paths.

### Phase 5 — omp extension

- [ ] Read the installed omp extension types/source for `ExtensionAPI.exec`,
      `tool_call`, command-input revision, handler context, and cancellation.
      Do not assume pi's helper exports or `ctx.signal` exist in omp.
- [ ] Implement the smallest native adapter:
  - probe `rtk --version` once at load;
  - intercept only `event.toolName === "bash"`;
  - ignore empty, already-prefixed, or disabled commands;
  - call `rtk rewrite <original-command>` with a bounded timeout;
  - accept only documented rewrite exit codes and non-empty output;
  - replace only `input.command`;
  - pass through on every failure.
- [ ] Use omp's real event revision mechanism. If handlers return a replacement
      input rather than allowing mutation, return the documented shape; do not
      depend on accidental mutation.
- [ ] Ensure headless task/subagent sessions also load the extension. Unlike
      `nvim-notify.ts`, RTK should not require `ctx.hasUI`: subagent Bash output
      also consumes model context and benefits from filtering.
- [ ] Verify omp's built-in `read`/`grep`/`glob`/LSP tools are unaffected.
- [ ] Exercise the same rewritten, passthrough, recursive, disabled, and
      missing-RTK paths as pi.

### Phase 6 — Documentation and invariants

- [ ] Update README navigation and the RTK section without breaking the
      existing `#rtk-token-optimizer` link.
- [ ] Update all four harness managed-files tables and fresh-machine commands.
- [ ] Update the Brewfile comment.
- [ ] Extend or add focused shell invariants for configuration that can regress
      silently:
  - exactly one guarded Claude RTK hook;
  - exactly one Cursor RTK Shell hook;
  - valid Cursor JSON;
  - expected adapter files present under their owning Stow packages;
  - no adapter contains hard-coded Homebrew or home-directory paths.
- [ ] Avoid tests that merely snapshot generated TypeScript source. Behavioral
      smoke checks below defend the observable contract.

## Verification

### Static checks

- Run the existing Claude settings invariant suite.
- Parse every changed JSON file with `jq empty`.
- Run the repository's applicable shell formatter/linter checks for changed
  shell tests or setup scripts.
- Run TypeScript diagnostics or each harness's extension/plugin loader against
  the three adapters; no unresolved host-package imports.
- Run `rtk verify`; expect all RTK hook-engine tests to pass.
- Run `rtk hook check 'git status'`; expect `rtk git status`.
- Run `rtk hook check` on an intentionally unsupported command; expect the
  documented no-rewrite result, not an invented generic wrapper.

### End-to-end smoke matrix

For each harness, start a fresh one-shot or interactive session with an
explicit instruction to use its shell/Bash tool for `git status`. Do not infer
success from adapter loading alone.

| Harness | Trigger | Required evidence |
|---|---|---|
| Claude Code | Bash `git status` | Existing hook still rewrites once; no nested `rtk rtk` command |
| Cursor Agent | Shell `git status` | Cursor hook fires and RTK history/audit records the rewrite |
| pi | Bash `git status` | pi extension rewrites; session continues normally |
| opencode | Bash/shell `git status` | plugin rewrites; nvim notification plugin still loads |
| omp | Bash `git status` | omp extension rewrites in main session and one task/subagent session |

Use `RTK_HOOK_AUDIT=1` plus `rtk hook-audit` if supported by the upgraded
version; otherwise compare `rtk gain --history` immediately before and after
each isolated smoke. Evidence must identify the host and command rather than
relying on the cumulative global count.

For pi, opencode, and omp, repeat one smoke with `RTK_DISABLED=1` and verify no
new rewrite record appears. Run one explicit `rtk gain` command through each
harness and confirm it is not rewritten recursively.

### Regression checks

- Cursor status line still renders after adding `hooks.json`.
- pi's Claude-shaped footer, theme, npm extensions, and nvim notification bridge
  still load.
- opencode still resolves its configured OpenRouter model and both plugins.
- omp still resolves model roles/config and its nvim notification extension.
- `printenv OPENROUTER_API_KEY` and model lists are unchanged; no provider or
  credential file is touched.
- Herdr/sidekick-launched sessions exercise the same per-harness integration;
  no Herdr-specific RTK files are introduced.
- `rtk gain` may retain its known false “No hook installed” warning for the
  guarded Claude hook, but `rtk verify` and the end-to-end Claude smoke must
  succeed.

      the tracked Stow link now owns that path.
- [ ] Remove dry-run scratch files and hook-audit environment overrides.
- [ ] Confirm no live config was replaced by an unreviewed `rtk init` patch.

## Acceptance criteria

- Claude retains exactly one guarded RTK hook.
- Cursor, pi, opencode, and omp transparently rewrite a supported shell command
  through RTK and preserve unsupported commands.
- No adapter rewrites `rtk ...` recursively.
- Missing RTK and `RTK_DISABLED=1` fail open.
- omp task/subagent Bash calls are covered without affecting native structured
  tools.
- OpenRouter, Herdr, sidekick.nvim, credentials, and mutable harness settings
  require no RTK-specific changes.
- Every durable integration is tracked in the appropriate Stow package and is
  documented in README.md.
- Fresh-machine instructions avoid RTK's duplicate-Claude-hook patch path.
